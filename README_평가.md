# 평가 시트 사용법

## 파일 구성

| 파일 | 용도 | 누가 |
|---|---|---|
| `manifest.json` | **시나리오·이미지·비교군 정의의 단일 권위** — 여기만 고치면 아래가 전부 따라간다 | 관리자 |
| `build_eval_sheets.py` | manifest + demo_backdata → 결과/평가 시트, 자립형 export 생성 | 관리자 |
| `CUJ_평가용.html` | **블라인드 평가 입력** — AI 평가와 다른 평가자 점수가 파일에 들어 있지 않다 | 평가자 |
| `CUJ_결과.html` | **결과 확인** — AI 평가 + 사람 평가 집계 (`eval_data.js` 로드) | 취합 담당 |
| `export/` | 외부 공유용 자립형 HTML (이미지 내장, JS 없음) | 공유 |
| `evals/` | 평가자들이 내보낸 JSON을 모으는 폴더 | 취합 담당 |
| `평가취합.bat` | `evals/`를 스캔해 `eval_data.js` 생성 (`collect_evals.py`) | 취합 담당 |
| `claude_eval.json` | AI 평가 원본 데이터 (카드 키 = `<시나리오 id>/<이미지 stem>`) | — |
| `AI평가_분석_260813.md` | **최신** AI 평가 분석 리포트 (114카드, 신규 7번·NB 비교군 반영) | 참고 |
| `AI평가_분석_260809.md` | 이전 판 (109카드, 구 넘버링). 비교용 스냅샷 | 참고 |

데이터는 `demo_backdata/` 아래에 있다.

```
demo_backdata/
  <시나리오 id>/<이미지 stem>/{before.jpg, after.jpg | after_1.jpg,after_2.jpg, result.json}
  _source_images/    원본
  _baseline_fivek/   Expert 참조본 (Adobe FiveK, 일부 시나리오만)
  _nano_banana/<시나리오 id>/<stem>.jpg   생성형 비교군 (멀티턴은 <stem>.jpg 가 최종 턴, _t1.jpg 는 중간)
```

## 카드 구성

한 카드는 **BEFORE · AFTER(턴별) · Nano Banana · Expert (FiveK)** 4열이다.

- **AFTER** — 평가 대상. Vibe Editor 결과. 2턴 시나리오는 `T1`, `T2` 로 나뉜다.
- **Nano Banana** — 같은 프롬프트를 `gemini-2.5-flash-image` 에 그대로 넣은 생성형 결과. **모든 카드에 있다.**
  픽셀 보존형이 아니라 이미지를 다시 생성하므로 구도·포즈가 바뀔 수 있다. 참고용이며 심사 대상이 아니다.
- **Expert (FiveK)** — 사진가가 직접 리터치한 참조본. `manifest.json` 의 `baseline: "fivek"` 인 시나리오에만 붙는다.
  없는 카드는 이 자리에 안내 문구가 들어가고 **Expert 대비 승패 문항도 나오지 않는다.**

## 평가자

1. `CUJ_평가용.html`을 브라우저로 연다 (더블클릭).
2. 화면 하단 바에 **이름을 입력**한다. 입력한 이름으로 저장되며, 이름을 바꾸면 다른 사람의 평가로 취급된다.
3. 카드마다 고른다.
   - **지시이행** 1–5 — 프롬프트가 요구한 변화가 실제로 일어났는가
   - **품질** 1–5 — 결과물 자체의 완성도 (아티팩트·과보정·경계선 등)
   - **Expert 대비** — Vibe승 / 비슷 / Expert승 (Expert 열이 있는 카드에만 표시)
   - 메모는 선택 입력. 같은 버튼을 다시 누르면 선택이 해제된다.
4. 입력은 브라우저에 **자동 저장**된다. 창을 닫았다 다시 열어도 이어서 할 수 있다.
5. 다 하면 하단의 **JSON 내보내기**를 눌러 파일을 받고, 취합 담당에게 전달한다.

### 평가 기준

평가 대상은 **Vibe Editor의 AFTER 결과물**이다. Expert(FiveK)와 Nano Banana는 참조선이며 심사 대상이 아니다.

Expert 열은 "목표가 같은" 시나리오에만 붙는다 — 필름 룩·크롭·피부 리터치처럼 FiveK 리터치본과
애초에 같은 것을 겨냥하지 않는 요청에는 비교 열을 두지 않고 지시이행·품질만 평가한다.

### 왜 블라인드인가

`CUJ_평가용.html`에는 AI 평가 결과와 다른 평가자의 점수가 **파일 자체에 존재하지 않는다**
(숨긴 것이 아니라 제거했다). 남의 판단에 끌려가지 않게 하려는 것이다.

## 취합 담당

1. 평가자들이 보낸 `eval_*.json` 파일을 **`evals/` 폴더에 넣는다.**
2. **`평가취합.bat`을 더블클릭**한다. `evals/`를 스캔해 `eval_data.js`를 다시 만든다.
3. `CUJ_결과.html`을 열거나 새로고침하면 반영된다.

한 사람이 여러 번 내보낸 파일이 섞여 있으면 **더 많이 채워진 쪽만** 사용한다.
JSON이 깨져 있으면 건너뛰고 콘솔에 `SKIP`으로 표시한다.

> `.bat`을 쓸 수 없으면 `CUJ_결과.html` 하단의 **JSON 직접 열기** 버튼으로 파일을 골라도 된다.
> 다만 이 방식은 새로고침하면 사라진다.

**평가 키는 시나리오 id 기반**(`07_예쁘게_해줘/a3391-...`)이다. 시나리오 폴더 이름을 바꾸면
기존 평가 JSON의 키가 어긋나므로, 이름을 바꿀 때는 `claude_eval.json`과 `evals/*.json`의 키도 함께 옮겨야 한다.

### 결과 시트에서 보이는 것

- 카드마다 **AI 평가 1줄** (지시이행 / 품질 / Expert 대비 / 코멘트)
- 카드마다 **사람 평가 집계 1줄** — 응답자 수와 **평균값**, 승패 분포, 익명 메모
- 시나리오·분류 헤더에 AI 평균 배지와 사람 평균 배지
- 하단 바에 **참여자 명단**

**개별 평가자가 어떤 점수를 줬는지는 표시하지 않는다.** 평균과 분포만 보여주고,
메모도 작성자를 밝히지 않으며 순서로 추정되지 않도록 정렬해서 표시한다.

## 시트 다시 만들기

데이터셋·프롬프트를 바꿨거나 평가가 갱신됐으면 아래를 실행한다 (프로젝트 루트에서).

```
backend/venv/Scripts/python.exe 260807_cuj_results/build_eval_sheets.py             # CUJ_결과 / CUJ_평가용
backend/venv/Scripts/python.exe 260807_cuj_results/build_eval_sheets.py --export    # export/ 자립형 3분할
```

`--export` 옵션: `--px 640` (더 가볍게), `--jpeg` (WebP 미지원 환경 대비). 기본은 장변 800px WebP.
내용이 같은 이미지는 한 번만 인코딩해 재사용하고, EXIF 회전은 픽셀에 구워 넣는다.

결과물을 새로 만들어야 할 때 (백엔드 `localhost:8002` 기동 필요):

```
backend/venv/Scripts/python.exe scripts/demo/run_manifest_cuj.py [시나리오 id ...] [--all|--force]
backend/venv/Scripts/python.exe scripts/demo/run_nano_banana.py  [시나리오 id ...] [--force]
```

## 외부 공유용 내보내기

`export/` 폴더의 파일들은 **외부 의존이 전혀 없는 자립형 HTML**이다.
이미지가 파일 안에 통째로 들어 있고 JavaScript를 한 줄도 쓰지 않아,
아무 서버·웹 메모장·게시판에 올려도 사진과 평가 내용이 그대로 보인다.

| 파일 | 크기 | 내용 |
|---|---|---|
| `CUJ_결과_1_기본보정.html` | 11.6 MB | 10시나리오 · 50카드 |
| `CUJ_결과_2_무드필름그레이딩.html` | 7.7 MB | 7시나리오 · 41카드 |
| `CUJ_결과_3_전문가대화형편집.html` | 4.7 MB | 4시나리오 · 23카드 |

3분할본을 같은 폴더에 함께 올리면 상단 링크로 서로 이동할 수 있고, 링크가 깨져도 파일명이 텍스트로 적혀 있다.

## 기술 메모

브라우저는 `file://`에서 `fetch()`로 로컬 파일을 읽지 못한다(CORS 차단).
그래서 `evals/*.json`을 `<script>`로 읽을 수 있는 `eval_data.js`로 변환해 두는 방식을 쓴다.
`평가취합.bat`이 하는 일이 그 변환이며, 이 때문에 JSON을 넣은 뒤 한 번은 실행해 줘야 한다.

`평가취합.bat`은 `backend/venv`의 파이썬을 사용한다. 경로가 바뀌면 `.bat` 안의 경로를 수정한다.
